# Donde los lectores de hoy y libspectrum leen distinto el mismo archivo, en los campos que el
# formato guarda. Cada grupo es una decisión pendiente (doc/formatos-sna-z80-tap.md, sección 6), y
# todos juntos son lo que un lector nuevo puede cambiar. Una línea que deja de pasar se borra en el
# commit que lo cambia; una que aparece se entiende antes de agregarla.

# SNA de 48K: libspectrum desapila el PC y sube el SP en 2. El lector de hoy deja el PC en 0x0072,
# el RETN de la ROM, que lo desapila al arrancar.
lone-ed-at-the-end.sna: sp: 0xff00, 0xff02
lone-ed-at-the-end.sna: pc: 0x0072, 0x8000
manicminer.sna: sp: 0x9cfc, 0x9cfe
manicminer.sna: pc: 0x0072, 0x87ab

# SNA de 128K: libspectrum lo lee como un Pentagon; el lector de hoy, como un 128K.
banks-5-on-top.sna: machine: SPECTRUM128K, PENTAGON
banks.sna: machine: SPECTRUM128K, PENTAGON

# PLTT: libspectrum escribe la paleta de ULAplus en 67 bytes (el último es el registro 0xff) y lee
# 66 o más; el lector de hoy exige 66 exactos, así que un SZX con ULAplus guardado por Fuse no abre.
libspectrum/szx-chunks/PLTT.szx: java refuses it (FILE_READ_ERROR), libspectrum reads it

# SCLD: el archivo es de un TC2048, una máquina que hoy no se lee de un SZX.
libspectrum/szx-chunks/SCLD.szx: java refuses it (UNSUPPORTED_SNAPSHOT), libspectrum reads it
